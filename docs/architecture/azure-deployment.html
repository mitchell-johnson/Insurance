The insurance core on Azure: what the templates create

Read from infra/*.bicep and deploy/k8s on main, 14 Nov 2026. Workloads sign in with managed identities federated to their Kubernetes service accounts (Workload ID) and reach the ledger nodes with their own cluster token; there are no account keys or connection strings. Two exceptions: ic-underwriting runs as ic-worker's service account and token, and ic-admin and ic-bootstrap run as ic-node's.

Designed and templated, not deployed. CI compiles every template and renders the manifests on each push. No subscription has been deployed to, so nothing here has run on Azure. main.bicep is deployed first; each module template is deployed on its own into the same resource group (docs/operations.md, "First deployment").
Resource group, New Zealand North (one region; voters in a second and third region are not provisioned)
AKS cluster (main.bicep): system pool across zones 1, 2, 3; namespace insurance-core; WireGuard between pods; network policy admits the ingress namespace only to front doors

ic-node-1 · zone 1

StatefulSet pod with a managed disk: replicas of all 64 partitions and the 12 module groups.

ic-node-2 · zone 2

Same. A disruption budget keeps two of three up during upgrades.

ic-node-3 · zone 3

Same. A node that loses its disk is replaced under a new number.

Deployments

ic-api, ic-portal, ic-worker, ic-customers, ic-documents, ic-group, ic-payments-pump, ic-reinsurance, ic-underwriting, ic-underwriting-intake, ic-unit-pricing, ic-finance-close; each with a disruption budget.

CronJobs

ic-close 00:05 NZ · ic-unit-orders every 15 min · ic-payments-drill Tuesday 09:30 · ic-admin suspended, run by hand.

Job and access

ic-bootstrap forms the groups, opens the first date, activates products. ConfigMap ic-cluster-access: each workload's grant (report mode until enforced).

Temporal (undecided)

Temporal Cloud, or self-hosted here with the optional PostgreSQL (deployPostgres). The manifests hold a placeholder address.

main.bicep: the core platform

  • Container Registry; Log Analytics and Application Insights
  • Storage: merkle-roots, cold-segments (write-once, cool tier), payments-evidence (write-once)
  • Key Vault (premium): merkle-root-signing, cluster tokens
  • Payments vault: bank signing key and bank credentials
  • Event Hubs namespace, hub policy-events
  • PostgreSQL for Temporal, off by default
Identities: ic-node, ic-worker (also ic-underwriting), ic-api, ic-portal, ic-payments

customers.bicep: the people master

  • PostgreSQL Flexible Server of its own, Entra sign-in only, TLS required, zone-redundant in prod
  • Key Vault key customers-kek; secret customers-index-key
  • Hubs customer-events, customer-priority
  • Write-once customers-erasures register (10-year lock at first prod deploy)
Identity: ic-customers

documents.bicep

  • Storage: documents-vault (version-level immutability), print-outbox
  • Key Vault key documents-kek, webhook key
  • Communication Services (email, SMS) and Event Grid delivery reports
  • Hubs documents-events, complaints-events
Identity: ic-documents

underwriting.bicep

  • Clinical store: own storage, no soft delete or versioning, on purpose (erasure)
  • HSM key clinical-key-wrap, wrap and unwrap only
  • Hubs underwriting-notices, -evidence, -delegates
Identity: ic-underwriting-intake (clinical)

reinsurance.bicep

  • Write-once reinsurance-records in the ledger account
  • Hub reinsurance-events
  • SFTP storage account, one local user per reinsurer
  • Log alerts and an on-call action group
Identity: ic-reinsurance

group.bicep

  • Quarantine storage for employer files, deleted after weeks
  • Defender for Storage malware scanning on upload
  • Hub group-events; secret group-fingerprint-salt
Identity: ic-group

unit-pricing.bicep

  • Inbound valuations account, scanned by Defender; the fund administrator writes under its own identity
  • Outbound holdings extract, write-once
  • Three log alerts and an on-call action group
Identity: ic-unit-pricing

finance.bicep

  • Storage finance-extracts, write-once
  • Read on merkle-roots
  • The finance ledger itself is a module on the nodes and needs nothing here
Identity: ic-finance-close

Microsoft Entra ID

App registrations and roles by deploy/entra/apps.sh (workforce and External ID tenants) and group-app.sh; one per reinsurer for the API.

Ingress controller

The insurer's own; exposes ic-api, ic-portal and the reinsurer API. Not in the templates.

Bank

mTLS channel from ic-payments-pump; credentials in the payments vault. No real bank chosen.

Second and third region

Five voters across three regions would survive a region loss; not written, and a data residency decision.
